# 008 — Continuous integration: GitHub Actions with Nix

Status: accepted (2026-11-05)

## Context

The repository is public on GitHub. Every test suite already runs locally
with `nix run .#test`, against the Firebase emulators and, for the app, in
Chrome. Nix provides the tools ([004](004-nix.md)); pub, npm and
firebase-tools fetch their own dependencies.

## Decision

GitHub Actions runs `scripts/test.sh` on every push to `main` and on every
pull request (`.github/workflows/ci.yml`).

- **Tools come from Nix.** Each job installs Nix and runs
  `nix develop .#<shell> -c bash scripts/test.sh <suites>`, so CI uses the
  versions in `flake.lock`, the same as locally. Everything in the CI shells
  is free software and comes prebuilt from `cache.nixos.org`.
- **One job per shell, in parallel:**

  | Job | Shell | Suites |
  |---|---|---|
  | Dart | `dart` | `checks` (analyze, format), `domain`, `app` |
  | Functions | `functions` | `functions` |
  | Emulators | `emulators` | `rules`, `functions-integration` |
  | Integration | `integration` | `integration`, in Chromium |

  `scripts/test.sh` takes the suites to run; with none it runs them all, as
  `nix run .#test` does.
- **The tests are impure,** not `nix flake check`: they need the network for
  pub and npm, firebase-tools downloads the emulators, and the app tests
  drive a real browser. Pure Nix builds are for release artifacts, if ever
  ([004](004-nix.md)).
- **Caches:** `actions/cache` keeps `~/.pub-cache`, `~/.npm` and the emulator
  downloads. There is no Nix store cache; the public cache serves everything
  the shells need.
- **Supply chain:** actions are pinned to commit hashes, the workflow's token
  is read-only, and no secrets are used: the tests run against the `demo-`
  project only. Integration screenshots are kept for seven days.
- **No Meson or CMake.** The code is built by Flutter and `tsc`; Nix provides
  the tools and `scripts/` the commands.

## Consequences

- A suite added to `scripts/test.sh` must also be added to a job.
- Deploying from CI ([001](001-backend.md), [005](005-distribution.md)) will
  need credentials; use workload identity federation, not a stored key.
- An Android job needs the `android` shell, whose SDK isn't in the public
  cache; it gets a Nix store cache when it is added.
